# ood_report_log.md フォーマット仕様

`ood_report_log.md` は、[ood_news_agent.py](../ood_news_agent.py) が実行ごとに
「新規」または「更新」として報告した項目を追記していく、報告済み項目ログです。
生成・追記処理は `append_log` 関数(`ood_news_agent.py`)が担い、次回実行時には
`load_log` が全文をそのままAgentへの入力として渡し、既報告項目との照合に使われます。

このファイルはリポジトリには含めません(`.gitignore` 対象)。実行環境ごとに
ローカルで蓄積されるものです。

## 全体構造

```markdown
# Open OnDemand 情報収集 報告ログ

## <YYYY-MM-DD HH:MM> 実行分

### <カテゴリ名>

- [<ステータス>] <タイトル> (<日付>) - <要約> - <URL>

### <カテゴリ名>

- [<ステータス>] <タイトル> (<日付>) - <要約> - <URL>
```

- ファイル先頭に `# Open OnDemand 情報収集 報告ログ` という見出しが1度だけ入る
  (ファイル新規作成時に付与される)。
- 実行ごとに `## <実行日時> 実行分` という見出しのセクションが末尾に追記される。
  時刻(分単位)まで含めることで、同じ日に複数回実行した場合でも実行分ごとに
  見出しを区別できる。
- 報告対象の項目が1件もない実行(すべて「変更なし」)では、セクション自体が
  追記されない。ログが不必要に肥大化しないようにするための挙動。

## 実行分セクションの内容

- 実行分見出しの下に、項目が存在するカテゴリのみ `### <カテゴリ名>` の見出しが並ぶ。
  カテゴリは以下の5種類で、常にこの順序で出力される。
  1. 新バージョンのリリース情報
  2. 開発ロードマップの更新・公開
  3. セキュリティ脆弱性情報
  4. コミュニティイベント
  5. その他のホットトピック
- カテゴリ見出しの下に、そのカテゴリで「新規」または「更新」と判定された項目が
  1行1件の箇条書きで並ぶ。

## 項目の1行フォーマット

```
- [<ステータス>] <タイトル> (<日付>) - <要約> - <URL>
```

| 要素 | 説明 |
| --- | --- |
| `<ステータス>` | `新規` または `更新` のいずれか。「変更なし」の項目はログに書かれない。 |
| `<タイトル>` | バージョン名・CVE ID・イベント名などの項目タイトル。 |
| `(<日付>)` | 項目の公開日・更新日(`YYYY-MM-DD`)。日付が不明な場合はこの括弧部分自体が省略される。 |
| `<要約>` | 日本語での簡潔な要約。ステータスが「更新」の場合、何がどう変わったかも含む。 |
| `<URL>` | 情報源のURL。 |

## 例

```markdown
# Open OnDemand 情報収集 報告ログ

## 2026-08-11 09:00 実行分

### 開発ロードマップの更新・公開

- [新規] Updated dashboard MOTD config options? (2026-07-06) - ロードマップ/機能要望カテゴリで、ダッシュボードの MOTD 設定オプション見直しに関する新規トピックが期間内に公開された。 - https://discourse.openondemand.org/c/feature-requests-and-roadmap-discussion/48

### セキュリティ脆弱性情報

- [更新] CVE-2026-26002 (2026-06-17) - Open OnDemand の Files アプリに関する CVE-2026-26002 で、NVD 記録に期間内更新があり、SSVC 情報と affected versions 情報が追加された。 - https://nvd.nist.gov/vuln/detail/CVE-2026-26002

### コミュニティイベント

- [新規] Open OnDemand Tips and Tricks - Americas (2026-08-06) - Open OnDemand 公式サイトのイベント欄で、2026-08-06 開催の Tips and Tricks - Americas が確認できた。 - https://www.openondemand.org/
```

## このファイルを手動編集する場合の注意

- 次回実行時、このファイル全文がAgentへの入力に含まれ、既報告項目との照合は
  LLMのテキスト理解によって行われる(構造化パースはしていない)。
  そのため厳密な機械的パース可能性は保証されないが、上記フォーマットから
  大きく外れると照合精度が下がる可能性がある。
- 項目を削除・改変すると、次回実行時にその項目が「新規」として再報告される
  ことがある。
