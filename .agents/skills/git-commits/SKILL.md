# Git コミット

本リポジトリのコミットメッセージは**すべて日本語**で記述する。

## 形式

```
変更内容の簡潔な説明

- 追加・変更の詳細
- 影響範囲
```

- **1 行目**: 変更内容を簡潔に説明する。接頭辞（`feat:` などの Conventional
  Commits）は使わない。
- **本文**: 1 行目の後に空行を置き、追加・変更の詳細と影響範囲を Markdown の
  箇条書きで記載する。見出しやコード表記が必要な場合も Markdown 記法を使う。

## 手順

1. `git status` と `git diff`（ステージ済みなら `git diff --staged`）で変更内容を
   確認する。関連しない変更が混ざっていないか確かめる。
2. 変更の意図を 1 行に要約し、詳細と影響範囲を箇条書きに落とす。
3. 改行と Markdown の書式を保つため、**必ずヒアドキュメント**でコミットする。

```sh
git commit -F - <<'EOF'
変更内容の簡潔な説明

- 追加・変更の詳細
- 影響範囲
EOF
```

`git commit -m "..."` を複数の `-m` で組み立てると箇条書きの書式が崩れるため
使わない。

## 注意

- ユーザーから明示的に依頼されない限り、コミットは作成しない。
- 実行時に生成される `ood_report_log.md` と `output/` は `.gitignore` 対象で
  あり、コミットに含めない。

## 例

✓ 良い例:

```
CSV/YAML ダウンロード機能を追加

- any のダウンロードエンドポイントを実装
- CSV出力で metrics を展開・正規化
- API ドキュメント更新
```

✗ 悪い例:

```
Add download feature
```

（英語で書かれており、本文がなく、影響範囲も分からない）
