# ルール: 関数設計（Python）

## 対象

- Python のすべての関数を対象とする。
- 関数の説明に関するルールでは、テストコードを除外する。
- Python のモジュール docstring は、テストを含むすべての Python ファイルを対象とする。

## 必須ルール

- モジュールの外部から呼び出される関数には、`_` で始まらない名前を付ける。
  - `_` で始まる名前は、そのモジュール内だけで使う非公開関数に限定する。
- 関数の処理本体は **80 行以内**に収める。
  - 関数冒頭の説明（docstring）は行数に含めない。
  - 処理中に書かれたコメントや空行は行数に含める。
- ループと条件分岐のネストは **3 段以内**に収める。
  - `for` / `while`、`if` / `switch` / `match`、`try` などの制御構造を対象とする。
  - 同一の `if` / `elif` / `else`、`try` / `except` は同じ段として数える。
- Python ファイルの冒頭に、そのモジュールの責務を説明する **モジュール docstring** を記載する。
- すべての関数に、**機能説明**と**その実装にした理由**を残す。
  - 機能説明と実装理由はブロックを分離する。
  - 実装理由の先頭には `[実装理由]` と書く

## コメントの書き方

- 関数定義の直前または関数先頭で、次の 2 点を必ず明記する。
  - この関数が何をするか（責務）
  - なぜその実装方針を採用したか（設計意図・トレードオフ）
- Python では docstringを使う。
  - docstring は Google スタイルに従って書く。
- モジュール docstring には、そのファイルが提供する機能または担う責務を簡潔に記載する。
- 日本語の docstring / コメントを折り返す際は禁則処理に従う。
  - 行頭に `、` `。` `)` `」` `』` `】` `,` `.` などの句読点・閉じ括弧を置かない。
